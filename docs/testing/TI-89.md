# TI-89: test harness and smoke suite

`pnpm test` runs every package's tests through Turborepo. This page covers how the API tests get a database, the one-line test users, the smoke suite, and the CI budget.

## What runs

| Package                  | `test` script                | What it checks                                                              |
| ------------------------ | ---------------------------- | --------------------------------------------------------------------------- |
| `@team-impact/api`       | `vitest run`                 | Mock API routes, database code on the real migrations, the smoke suite      |
| `@team-impact/portal`    | `vitest run`                 | The portal shell renders and routes by role (`src/App.test.tsx`), pages     |
| `@team-impact/athlete`   | `expo export --platform web` | The athlete app bundles for web (a broken import or route fails the export) |
| `@team-impact/contracts` | `vitest run`                 | Zod contracts and the access policy                                         |
| `@team-impact/ui-tokens` | `vitest run`                 | Contrast pairs and that `tokens.css` is up to date                          |

## The database: PGlite locally, Postgres in CI

`apps/api/src/test/db.ts` gives every caller its own throwaway database with the real Drizzle migrations (`apps/api/drizzle`) applied:

```ts
const testDb = await createTestDb(); // in beforeAll, with DB_TIMEOUT_MS
await testDb.seed(fixtureRows()); // optional: the mock world as rows
const rows = await testDb.rows(sql`select ...`); // raw SQL, same shape on both drivers
await testDb.close(); // in afterAll
```

- **Locally (no env var):** an in-memory [PGlite](https://pglite.dev) instance. No Docker, no server, nothing to clean up.
- **With `TEST_DATABASE_URL` or `DATABASE_URL` set (CI):** a real Postgres. Each `createTestDb()` runs `create database ti_test_<random>` on that server, migrates it, and `close()` drops it (`with (force)`). The database named in the URL is never touched, so the role needs `CREATEDB`. `TEST_DATABASE_URL` wins if both are set.
- `testDb.driver` says which one you got. Use `testDb.db` (typed as the app's `Db`) for Drizzle queries and `testDb.rows()` for raw SQL, so a test passes on both.

The migrations qualify every type and table with `"public"`, which is why isolation is a fresh database rather than a schema per test.

To run the Postgres path locally, point it at any Postgres you can create databases on:

```sh
# the repo's local Postgres 17 (docker-compose.yml), the same major version as CI
docker compose up -d postgres
TEST_DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/team_impact pnpm --filter @team-impact/api test
```

Careful: if your shell exports `DATABASE_URL` for development, tests will create and drop `ti_test_*` databases on that server. Unset it to use PGlite.

## One-line test users

`apps/api/src/test/agents.ts`:

```ts
const { app, world, close } = await mockApp(); // the mock API on a world you can inspect
const parent = await signInAs(app, 'parent'); // signed in as the fixture parent
const res = await parent.get('/me'); // { status, body, text }
await parent.post('/communities/…/posts', { text: 'Hi' });
const stranger = anonymous(app); // no session
```

- `signInAs(app, role, { newcomer })` works for every role (`staff`, `coach`, `athlete`, `parent`, `teen`, `recruiter`, …). The agent keeps cookies between calls, so a sign-up or sign-out carries over. `agent.me` is the signed-in user.
- **Real login doesn't exist yet** (argon2 + signed cookies is a later ticket). `signInAs` uses the mock's `/auth/dev-sign-in`, which sets the same signed session cookie. When real login lands, change `signInAs` to sign in with the seeded password (`team-impact-dev`) and tests keep working.
- For the database app: `const app = await dbApp(testDb)` then `const recruiter = await dbUserAs(app, testDb, 'recruiter')` inserts a user of that type and returns an agent (with `recruiter.id`). The app reads who's signed in from a test-only header passed through `buildApp({ currentUserId })`; production never sets that option.

## The smoke suite

`apps/api/src/test/smoke.test.ts`, the first real tests through the harness:

| Test                              | Mode     | What it proves                                                                                                                                                                                                                            |
| --------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sign-up, session, sign-out        | Mock API | Open sign-up creates an account and session; `/me` works; sign-out ends it                                                                                                                                                                |
| Every role signs in in one line   | Mock API | `signInAs` for all six roles; strangers get 401 (dev sign-in stands in for real login)                                                                                                                                                    |
| Consent-filtered athlete query    | Mock API | Recruiter search returns only athletes with a published card and open-to-recruiting; never the teen                                                                                                                                       |
| Write-gate bypass attempts fail   | Mock API | A teen posting outside their team, a parent posting, a recruiter posting into an official community: all 403, nothing stored. The teen's own-team post works (the gate isn't a blanket no)                                                |
| Seeded schema                     | Database | `fixtureRows()` inserts into the migrated schema                                                                                                                                                                                          |
| Recruiter-visible athletes in SQL | Database | The published-card + open-to-recruiting query on real tables matches the mock                                                                                                                                                             |
| PRD privacy invariants            | Database | No recruiter memberships; no teen in a medical community; search opt-ins only in official open interest communities; children are never users and have no birth date column; every teen has a `parent_agreed` record with a terms version |
| Forged client event               | Database | A client claiming a server-only event (`card.published`) gets 400; a stranger gets 401; nothing is logged                                                                                                                                 |

The rest of the API suite (`src/mock/*.test.ts`, `src/events-log.test.ts`, `src/test/terms.test.ts`, …) runs in the same `pnpm test`.

## Adding a test

1. Put it next to the code (`src/mock/<area>.test.ts`) or, for cross-cutting checks, in `src/test/`.
2. Mock-API tests: `mockApp()` + `signInAs()`; close the app in `afterEach`.
3. Database tests: `createTestDb()` in `beforeAll(…, DB_TIMEOUT_MS)`, `close()` in `afterAll`. If tests write, truncate between them (`truncate users cascade` through `testDb.db.execute`, as `src/events-log.test.ts` does) or give each test its own rows. Use `testDb.rows()` for raw SQL.
4. Run it both ways before pushing: `pnpm --filter @team-impact/api test`, and with `DATABASE_URL` if you have a Postgres.

## CI

`.github/workflows/ci.yml`:

- A `postgres:17` service with a health check. The **Test** step sets `DATABASE_URL=postgres://postgres:postgres@localhost:5432/team_impact_test`; `turbo.json` declares `DATABASE_URL` for `test`, so Turborepo passes it through (it filters undeclared env vars, which is why CI doesn't use `TEST_DATABASE_URL`).
- Typecheck, lint and build run first; then **Test** runs `pnpm turbo run test` with `timeout-minutes: 5`, the TI-89 budget. A slower suite fails instead of quietly growing.
- On pull requests only changed packages and their dependents run (`TURBO_FILTER`).
- **Blocking merge:** a failed job blocks merge only once the `check` job is a required status check in the GitHub branch protection rule for `main` (repository settings; not in this repo's files).

## Timing

Measured on a dev container (Oct 30, 2026):

| Suite                                         | Time  |
| --------------------------------------------- | ----- |
| API, 25 files / 421 tests, Postgres 16 server | ~20 s |
| API smoke + terms + legal-docs, PGlite        | ~9 s  |
| Portal, 6 files / 43 tests                    | ~10 s |
| Athlete `expo export --platform web`          | ~41 s |

Turborepo runs packages in parallel, so the test step is about a minute plus install; well inside 5 minutes. PGlite boots and migrates in a few seconds per file, which is why database tests use `DB_TIMEOUT_MS` (30 s) for their setup hooks.
