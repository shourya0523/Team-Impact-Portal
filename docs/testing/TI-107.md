# TI-107: testing the terms, privacy policy and acceptable use

What to check for the legal text users accept at sign-up and the record of which version they accepted. The documents are in `docs/legal/`; the versioning rules are in `docs/legal/README.md`.

## Automated tests

Run `pnpm --filter @team-impact/contracts test` and `pnpm --filter @team-impact/api test`.

| File                                   | Covers                                                                                                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/contracts/src/legal.test.ts` | One shared version for the three documents; `TermsVersion` accepts only the current version; open, recruiter and new-coach sign-up reject a missing or old `termsVersion`; a teen without `parentAgreed: true` is rejected |
| `apps/api/src/test/terms.test.ts`      | Mock API: missing/old version → 400 and no account; teen without parent agreement → 400; accepted version recorded for an adult, a teen (plus `parent_agreed`), a new coach, and a recruiter on approval                   |
| `apps/api/src/test/legal-docs.test.ts` | Each document's `**Version:**` header equals `CURRENT_TERMS_VERSION`; drafts say DRAFT and only drafts; the required clauses are still there; the counsel note lists all five PRD §11 questions                            |
| `apps/api/src/test/smoke.test.ts`      | Seeded database: every teen has a `parent_agreed` consent record with a terms version                                                                                                                                      |

When you change any legal text, bump `CURRENT_TERMS_VERSION` and all three headers together; `legal-docs.test.ts` fails otherwise.

## Manual QA

Run the mock stack: `pnpm dev:mock`. Use a fresh email each time.

### Athlete app: adult sign-up

1. Open **Sign up**, enter a birth date 20 years ago, pick **Athlete**, continue.
2. On **Your account**, check the **Before you join** card lists **Terms of Use**, **Privacy Policy** and **Acceptable Use Policy** and shows the version (`2026-11-draft.1`).
3. The checkbox reads "I agree to the Terms of Use, Privacy Policy and Acceptable Use Policy". **Create account** stays disabled until it is ticked.
4. Create the account. In the browser's network tab the `POST /auth/sign-up` body has `"acceptTerms": true` and `"termsVersion": "2026-11-draft.1"`.

### Athlete app: teen sign-up (13–17)

1. Enter a birth date 15 years ago. You go straight to **Joining as a teammate** (no role picker).
2. The **Teen terms** card names all three documents and **Continue** is disabled until "A parent or guardian agreed to me joining" is ticked.
3. Finish the account step. The request body has `"role": "teen"`, `"parentAgreed": true` and the `termsVersion`.
4. Negative: with the API running, send the same request with `parentAgreed` removed (e.g. with curl). Expect 400 with the issue on `parentAgreed`, and no account.
5. Under 13: a birth date 12 years ago goes to the under-13 page; no account is created.

### Version checks against the API

```sh
# Old version: expect 400, issue path body.termsVersion
curl -s -X POST localhost:3000/auth/sign-up -H 'content-type: application/json' \
  -d '{"email":"qa1@example.org","password":"correct horse battery","firstName":"Q","lastName":"A","birthDate":"2004-01-01","role":"athlete","acceptTerms":true,"termsVersion":"v2.0"}'
```

Repeat without `termsVersion` (400) and with the current version (201). Adjust the port to your `pnpm dev:mock` API.

### Coach invite

1. Open the lacrosse invite link from the mock fixtures (`/invite/invite-tufts-lacrosse-first-coach`) signed out and create the account.
2. The request body's `newAccount` carries the current `termsVersion` (the app's API layer adds it).
3. Known gap: the invite screen's checkbox still says "Terms and Privacy Policy" and doesn't name the Acceptable Use Policy; that screen belongs to another ticket.

### Portal: recruiter sign-up

1. Open the portal's **Sign up** page. The form names the three documents and the version above the checkbox, and the checkbox reads "I agree to the Terms of Use, Privacy Policy and Acceptable Use Policy".
2. Submit with a partner work email (e.g. `@northbeam.com`). The `POST /auth/recruiter-sign-up` body has the `termsVersion`.
3. Sign in as staff and approve the sign-up; the acceptance is recorded at approval with the version from the request.

### Accessibility and design

- The document list and labels are read by a screen reader (VoiceOver/TalkBack, and the browser on the portal).
- No hardcoded colours or spacing: `pnpm lint` passes.
